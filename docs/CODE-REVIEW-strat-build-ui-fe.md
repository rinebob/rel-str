## Thermo-nuclear

- **MAJOR:** `loadInstances$()` combines `where('userId', '==', uid)` with `orderBy('createdAt', 'desc')`. Because the ordering field differs from the equality filter field, Firestore requires a composite index. Without it the query will fail at runtime in production/emulator. The existing `SpreadListService` avoids this by filtering in memory after fetching; adopting the same pattern removes the deployment dependency.
  - File: `src/app/features/rh-agent/services/strategy-builder.service.ts`, lines ~43-45

- **MINOR:** `normalizeTimestamp` defaulting missing timestamps to `new Date().toISOString()` in the backend repository was noted previously and is acceptable because validation prevents missing timestamps from reaching normalization.

## Fixes applied

### 1. Generate deterministic instance IDs

`strategy-builder.service.ts` now imports `generateInstanceId` from `@options-strategy-engine/id` and builds the document path with the naming-convention ID before calling `setDoc`. Path aliases were added to `tsconfig.json` and `jest.config.js`.

### 2. Sort in memory instead of Firestore `orderBy`

Removed `orderBy('createdAt', 'desc')` from the Firestore query. `loadInstances$()` now fetches by `userId` equality and sorts the returned array in memory by lifecycle state then created date.

- File: `src/app/features/rh-agent/services/strategy-builder.service.ts`

This removes the need for a composite index and matches the existing `SpreadListService` pattern.
